Imported preferences alter a browser request

Start Full PTK SAST and IAST before the action. The target sends one same-origin preview request; it does not change the global object prototype or contact an external host.

  1. Setup: open the review target with Full IAST running. Focus the JSON field, select all, and type the same prepared value, {"__proto__":{"credentials":"include"}}, using the browser keyboard. The prefilled value alone does not create the user-input source PTK needs for this IAST finding.
  2. Core action: press Import and load preview.
  3. Vulnerable outcome: the request reads an inherited credentials option and the page displays PREFERENCE-INHERITED-REQUEST-OPTION.
  4. Repaired outcome: repeat the same input and import on the repaired target; only an allowed own option is used and the page displays PREFERENCE-ALLOWLISTED-REQUEST-OPTION.

Reset: press Reset preferences or reload the target. Use a fresh PTK scan when repeating the finding comparison.

Exact PTK evidence to inspect: Full 10.0.0 Firefox positive/repaired controls, which re-enter the JSON before import, confirm iast_prototype_pollution_impact / prototype_pollution_fetch_init only on review. The browser's preview token proves request behavior, not an IAST finding. The corrected manual Edge journey still needs confirmation.
