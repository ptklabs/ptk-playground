Lab / Manual PTK proof

GraphQL cross-owner order query

Run npm run demo. In Full PTK, capture the browser's GraphQL POST in Proxy, then use Request Builder to compare the same Alice session and query on the review and repaired endpoints. This is manual PTK proof, not a claimed automatic BOLA finding.

  1. Setup: open the review page, start Alice's synthetic session and leave Bob's order selected.
  2. One action: press Query order.
  3. Vulnerable outcome: HTTP 200 includes data.order.owner: "bob" for Alice.
  4. Repaired outcome: repeat the identical request at the repaired page; it returns data.order: null with FORBIDDEN. Alice's own order still returns data.

Reset: choose Alice again or restart the local runtime; this query does not change data. A signed-in local session may also call POST /api/labs/reset.

Exact PTK evidence claim: one captured POST with the documented Order($id: ID!) operation, variables.id: "order-bob", and Alice's session, paired with the vulnerable Bob object and repaired FORBIDDEN response. A browser-only fixture result is not a PTK finding.
