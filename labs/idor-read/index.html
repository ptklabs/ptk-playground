Read another user's order

Use the loopback runtime. Start synthetic Alice and Bob sessions in separate browser contexts. In Full PTK, capture Alice's own-object request in Proxy and compare the altered object ID with the unaltered request; no automatic BOLA finding is claimed.

  1. Setup: open the review route as Alice and select Bob's order.
  2. One action: press Read order.
  3. Vulnerable outcome: HTTP 200 returns an object whose owner is Bob while the actor is Alice.
  4. Repaired outcome: the same Alice-to-Bob request on the repaired route returns 403; Bob can still read his own object.

Reset: choose Alice again or open fresh isolated contexts. This read does not mutate state; restarting the local server also clears sessions.

Exact PTK evidence claim: manual Proxy/Request Builder proof is the captured same-session GET with only the order ID changed, paired with the 200/Bob versus 403 responses. Fixture success is not an automatic finding or a current Full 10.0.0 qualification.
